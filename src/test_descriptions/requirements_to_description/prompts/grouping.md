Разбей входные атомарные требования на комплексные тесты по основным операциям DUT.

Комплексный тест — переиспользуемая подготовка и общий цикл воздействия/наблюдения,
внутри которого выполняются подпроверки разных требований. Атомарное требование,
отдельное поле пакета и отдельный ожидаемый результат не равны самостоятельному тесту.

Сначала выдели основные операции устройства, затем собери вокруг каждой все
совместимые АТ. Различия значений полей, корректный или ошибочный вход,
пересылка или отбрасывание задаются вариантами воздействия и ожидаемых результатов
внутри комплексного теста. Они не являются самостоятельными основаниями разделения.

Формирование сообщения и обработка принятого сообщения могут задавать разные
основные операции. Определяй их по смыслу требований. Разделяй группы, когда меняется
сама операция либо необходим самостоятельный процесс подготовки и выполнения,
который нельзя представить подпроверкой существующего теста.
Описание структуры пакета не является отдельной операцией DUT. Разбор заголовка,
проверка его полей и дальнейшая пересылка/отбрасывание могут быть подпроверками
одной операции обработки принятого трафика, а не разными комплексными тестами.
Перед ответом объедини группы, различающиеся только проверяемым полем или вариантом
пакета. Одновременно не объединяй независимые операции только из-за общего протокола.

Правила трассировки:
- Группируй только записи из atomic_requirements. Их коды — единственные допустимые
  значения atomicRequirementCodes. context_requirements содержит родительский контекст;
  его коды в ответ не включай.
- Каждое АТ включай максимум в одну группу. Все MUST должны быть покрыты.
- MAY можно не включать, если оно требует отдельной подготовки или неподтверждённой функции.
- Если АТ содержит связанные проверки разных аспектов, назначь его одной подходящей
  группе и сохрани все его подпроверки. Связанные дополнительные операции допустимы;
  игнорировать часть АТ, дублировать или придумывать коды нельзя.

Верни только JSON: объект tests с массивом объектов, у каждого только поле
atomicRequirementCodes — непустой список кодов АТ. Не добавляй названия и описания.
