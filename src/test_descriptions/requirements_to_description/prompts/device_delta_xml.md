По выбранным атомарным требованиям, топологии и входной базовой конфигурации
Juniper EX4650 сформируй Delta Junos OS XML для текущего теста.

База уже задана. Сохраняй её настройки и включай в Delta только необходимые изменения.
Изменения пакетов и ожидаемых результатов на Xinertel не являются изменением DUT.
Сначала проверь предварительную подготовку в базе. Отсутствие специальных настроек
полей GRE не означает, что сам GRE-туннель уже настроен. Для IPv4 нужны unit,
tunnel source/destination и family inet; для формирования GRE нужен путь отправки
IPv4 в туннель (подключённая сеть туннеля либо маршрут через его логический интерфейс).
Недостающую подготовку добавь в дельту; существующую повторять не нужно.
Если база уже обеспечивает необходимые условия теста, верни <configuration/>.
Не добавляй настройки лишь ради непустого XML.

Учитывай обычный путь трафика и достижимость соседей. Используй имена физических
интерфейсов из базы. Известные значения и параметры базы переиспользуй;
новые неизвестные значения обозначай как ${PARAMETER}, различая IP и CIDR.
Не выдумывай теги для Version, Reserved, Checksum и других проверяемых полей.
Используй документированный контекст Junos; неподтверждённые возможности
не превращай в настройки. Существенные ограничения можно указать XML-комментарием.

Верни только XML с корнем configuration, без JSON, Markdown, RPC, validate и commit.
Это предложение изменений, применение конфигурации не выполняется.
