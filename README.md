# Генератор описаний тестов

Прототип для дипломной работы: **требования + базовая XML → группы тестов →
описания и топология → Delta XML → проверка и JSON → текст конфигурации в README**.

## Входные данные

- `requirements/*.json` — требования.
- `configurations/*.xml` — входные базовые конфигурации. База выбирается в меню
  или передаётся через `--base`; программа её не изменяет.
- `docs/test_description_format.md` — локальный документ формата README.

База по умолчанию — локальный файл `configurations/BASE_RFC2784.xml`.
Добавьте свою базовую XML-конфигурацию в эту папку перед запуском.
Идентификатор базы — имя файла без расширения.

## Установка

Нужен Python 3.11 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install "openai>=1.0.0" "pydantic>=2.0.0" "python-dotenv>=1.0.0" "doit>=0.36.0" "questionary>=2.0.0" "rich>=13.0.0"
cp .env.example .env
export PYTHONDONTWRITEBYTECODE=1
```

Сам проект устанавливать не нужно. Локально `doit` настроен в `~/.zshrc`
и использует `.venv` текущего проекта. URL, ключ и модель задаются в `.env`:

```env
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=<ваш ключ>
LLM_MODEL=openrouter/free
```

## Запуск

```bash
doit          # Меню: требования → база → действие
doit generate # Полный цикл для REQUIREMENTS из dodo.py и базы по умолчанию
doit draft    # Черновики без LLM; разбиение по одному АТ — техническая заглушка
doit list
doit clean    # Удалить outputs
```

Явные входные данные:

```bash
.venv/bin/python -B main.py requirements/GRE_RFC2784.json --base configurations/BASE_RFC2784.xml
```

Каждый запуск создаёт отдельный каталог `outputs/requirements_to_description/<имя JSON>/descriptions/run_…/`.
Параметр `--output` задаёт родительский каталог. Старые прогоны не перезаписываются.
После сбоя выберите продолжение в меню или добавьте `--resume`: сохранённые этапы
используются только при совпадении требований, базы, промптов, кода и модели.

## Генерация и результат

Группировка получает отдельные списки АТ и родительского контекста. Проверяются
коды, отсутствие повторов и покрытие MUST; смысловое качество групп оценивается отдельно.
Затем формируются код, краткое описание и топология каждого теста.
Теги и трассировка требований собираются из JSON.

Для конфигурации LLM получает выбранные АТ, топологию и входную базу и возвращает
только Delta XML. Python проверяет XML и необходимые условия IPv4 GRE по базе и дельте:
unit, endpoints, family inet и путь инкапсуляции, когда его требуют АТ.
При ошибке выполняется одна попытка исправления. После успешной проверки отдельный
запрос формирует текст раздела конфигурации по JSON дельты.
Пустая дельта допустима, если подготовка уже есть в базе.

В каталоге прогона сохраняются:

- `groups.json` — группы, трассировка и прогресс;
- `grouping.*` — запрос, ответ и метаданные группировки;
- `requirements.json`, `base_configuration.xml` — требования и очищенный контекст базы;
- `test_001.md`, … — описания тестов;
- `test_001.delta.xml`, `test_001.configuration.json`, … — дельты и локальный разбор;
- `test_001.delta.initial.xml`, … — первоначальные дельты, если понадобилось исправление.

Все промпты вынесены в `src/test_descriptions/requirements_to_description/prompts/`.
Разделы воздействия, критерия прохождения и дополнительной информации пока содержат TODO.

## Пределы проверки

Локальный профиль не заменяет Junos XSD, NETCONF validation или проверку на устройстве.
Объединение известных настроек базы и дельты учитывает merge/replace/delete/remove,
но не вычисляет реальное состояние DUT. Направление проверки определяется по тексту АТ;
связи параметров, конкретный трафик и достаточность сценария требуют отдельной оценки.
Программа не применяет конфигурацию и не выполняет commit.

Входные XML могут содержать именованные параметры неизвестных адресов.
Эталонные группы не подставляются вместо ответа LLM.

`requirements/`, `configurations/`, `docs/`, `.env`, `outputs/` и `experiments/` исключены из Git.
Локальные входные документы после клонирования нужно добавить отдельно.
Локальные входные данные и `experiments/` сохраняются после `doit clean`.
